关于count计数

count() 计数对于任何非null的值都会纳入计算，所以如果使用 count() 函数需要进行条件判断，就需要给出如下形式：

1

count(CONDITION or null)

则可以在不满足条件 condition 使返回null, 使count不对该值计数，实现count有条件的计数。

查看当前查询的计划

在字段 select 前使用 explain 可以得出当前优化器给出的执行计划，判断是否会使用索引进行查询，

+----+-------------+-------+------------+------+---------------+------+---------+------+------+----------+-------+
| id | select_type | table | partitions | type | possible_keys | key  | key_len | ref  | rows | filtered | Extra |
+----+-------------+-------+------------+------+---------------+------+---------+------+------+----------+-------+
|  1 | SIMPLE      | user  | NULL       | ALL  | NULL          | NULL | NULL    | NULL |    4 |   100.00 | NULL  |
+----+-------------+-------+------------+------+---------------+------+---------+------+------+----------+-------+

其中 key 表示当前使用的索引类型， type=ALL 则表示使用全表搜索。

type 表示 select 种类，有几种常见的值:

  • ALL 全表扫描，一般找不到查询语句里的索引键，就采用全表查询；
  • index 全索引扫描
  • range 索引范围扫描
  • ref 非唯一索引扫描
  • eq_ref 唯一索引扫描
  • const 仅有一条结果的逐渐或唯一索引扫描

从上至下，效率逐级增高，一般尽量避免全表扫描和全索引扫描，在执行查询前，可以检查对应的select 类型是否合理。

extra 中值得注意的值：

  • using index 使用 覆盖索引，也即查询中的普通索引已经可以获得对应的列，则不需要使用主键索引取得对应的行(这样减少了搜索B+树的成本，不需要回表操作)；
  • using index condition 索引下推，由存储引擎进行过滤操作，将符合条件的列对应数据回表，防止直接回表造成 Server 进行判断过滤操作

MySQL中的锁

三种等级：全局锁，表级锁，行锁。

全局锁：flush tables with read lock，对整个数据库实例加锁，用于保证数据库的完整性，防止其他线程对数据库的操作。解锁采用：unlock tables.

一般仅在对数据库备份时采用全局锁，防止备份过程出现不一致情况。

如何避免全局锁加锁： 采用 MVCC 提供的 Read View，这样备份过程是在 Read View 下操作，可以保证一致性，具体如何操作？备份前开启事务即可。

例子：

1

> mysqldump --single-transaction -uroot -p ggdb user > tmp.sql

不太常用的功能

视图

一种简化表查询的方式，可以认为是一种虚拟表，但是实际并没有占用实际存储，而是访问时才开始执行查询。

使用视图的目的一般都是简化 sql 语句的表达，隐藏复杂的sql;

创建也非常简单：create view '虚拟表名' as '正常的select 语法，一般写 view 都会写跨表联结的表示'

可以当做正常的表使用: select * from '虚拟表名'

一般应该将视图用于检索（SELECT语句）而不用于更新 (INSERT、UPDATE和DELETE), 即使部分虚拟表支持修改操作。

存储过程

存储过程是一种将查询的结果保存到变量的一种 调用,

创建过程：

CREATE PROCEDURE productpricing(
    OUT pl DECIMAL(8,2),
    OUT ph DECIMAL(8,2),
    OUT pa DECIMAL(8,2),
)
BEGIN
    SELECT Min(prod_price) as priceaverage
    INTO pl
    FROM products;
    SELECT Max(prod_price) as priceaverage
    INTO ph
    FROM products;
    SELECT Avg(prod_price) as priceaverage
    INTO pa
    FROM products;
END

执行过程：

CALL productpricing();

删除过程：

DROP PROCEDURE IF EXISTS

不常见的概念

数据库的范式

第一范式 1NF：数据项不可分 第二范式 2NF：非主属性都需要完全依赖主键 第三范式 3NF: 非主属性不能部分依赖主键，也不能传递依赖主键
