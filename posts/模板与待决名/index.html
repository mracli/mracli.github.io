模板与待决名

待决名1 (dependent name)

在模板（类模板和函数模板）定义中，某些构造的含义可以在不同的实例化间有所不同。特别是，类型和表达式可能会取决于类型模板形参的类型和非类型模板形参的值。

template<typename T>
struct X : B<T> // "B<T>" 取决于 T
{
    typename T::A* pa; // "T::A" 取决于 T
                       // （此 "typename" 的使用的目的见下文）
    void f(B<T>* pb)
    {
        static int i = B<T>::i; // "B<T>::i" 取决于 T
        pb->j++; // "pb->j" 取决于 T
    }
};

这里的B<T>, T::A, B<T>::i, pb->j 都是待决名，因为需要都需要根据传入的模板参数 T 决定实际的类型。

歧义消除

在上述代码中typename T::A* pa 这一段中，由于 * 导致不能确定 T::A 是否为类型还是运算符的参数。所以需要在签名通过符号 typename 指明 T::A 是一个待决名而不是其他的变量。

除了使用 typename 消除类型的歧义，模板名也会出现歧义，使用 template 消除歧义：

template<typename T>
struct S{
    template<typename U>
    void foo() {}
};
 
template<typename T>
void bar(){
    S<T> s;
    s.foo<T>();          // 错误：< 被解析为小于运算符
    s.template foo<T>(); // OK
}

关键字 template 可以放在运算符 :: -> . 之后：

  • T::template foo<X>()
  • s.template foo<X>()
  • this->template foo<X>()
  • typename T::template iterator<int>::value_type v

绑定逻辑2

在模板中，待决名和非待决名的绑定逻辑也不一样，非待决名会在模板定义处绑定，模板实例化时并不会寻找最匹配的。

#include <iostream>

void g(double) { std::cout << "g(double)\n"; }

template<class T>
struct S{
    void f() const{
        g(1); // "g" 是非待决名，现在绑定
    }
};

void g(int) { std::cout << "g(int)\n"; }

int main(){
    g(1);  // 调用 g(int)

    S<int> s;
    s.f(); // 调用 g(double)
}

非待决名：检查该模板的定义时将进行无限定的名字查找 待决名：它的查找会推迟到得知它的模板实参之时

#include<iostream>

template<class T>
struct X {
    void f()const { std::cout << "X\n"; }
};

void f() { std::cout << "全局\n"; }

template<class T>
struct Y : X<T> {
    void t()const {
        this->f();
    }
    void t2()const {
        f();
    }
};

int main() {
    Y<void>y;
    y.t();   // 待决名等待确认模板形参才开始查找
    y.t2();  // 非待决名，直接查找，类内无定义，在全局环境中找到定义
}
