Docker的简单应用

记录自己使用到 Docker 的情况

发表于 2024/10/27 更新于 2024/11/24
作者 墨墨鱼
3 分钟阅读

Docker 对于个人开发者或者小公司有以下的作用：

  • 统一开发环境
  • 快速部署测试环境

进一步 Docker 也可以与 CI/CD 操作继承，利用类似Travis, Jenkins的持续交付、部署工具来完成重复度高的部分。

记录博客的码字环境

我的博客是基于 github pages 的静态网页，所采用的模板为 Chirpy, 所有的博客内容都是以 .md 格式文件进行编写，并使用 jekyll 管理和发布博客内容到静态页面中。

该博客作者未考虑到私有数据的保存(虽然对于静态网页这种Serverless应用来说也没有什么秘密)，我修改了一下博客项目 CI/CD 的流程，从原始的：

  1. 直接将仓库推送到github
  2. github upload-pages-artifact@v3 部署

中添加了一层仓库，将该仓库转为私有，当push到私有仓库时进行 CI/CD, 部署至公开仓库，最后更新github pages，但对于编写码字的环境，仍然需要重新配置。

现在只需要通过 docker ruby 容器下编写即可，这里以我的环境作为例子：

1
2

FROM ruby:3.1.5 AS blog_env
COPY . /blog_env
WORKDIR /blog_env
RUN bundle install
RUN rm *
CMD [ "/bin/sh" ]

然后使用：

1

docker build -t blog_env

这样就可以构建出对应的码字环境，然后创建并运行容器时将我们的博客地址挂在在容器环境中:

1
2
3

docker run --rm -itd --name blog_space \
       -v /path/to/proj:/home/blog_space \
       -w /home/blog_space blog_space

当然以上所述只是为了走一遍构建的流程，实际上我们不需要这么做，vscode 中 DevOps 已经有对应的 容器，我们可以直接选择 jekyll 就可以一键安装对应的环境。

意料之外的情况

vscode + devops 环境中，将 github 项目挂载到容器环境还是会有小问题，我这里就碰到了：

容器环境下操作挂载目录，虽然可以及时同步，但是重命名文件的操作不会生效，思考原因在于vscode封装了这一操作（进行该操作时可以看到正在运行文件重命名参与者），使得重命名过程找不到文件。

解决办法：不挂载目录，而是直接将项目拉取到容器中。

统一开发和测试环境

通过使用相同镜像，可以使得开发环境和测试环境保持一致，同时可以对测试环境进行精简，仅保留支持运行的环境，可以进一步降低测试环境容器占用的空间。
